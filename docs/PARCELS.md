# 取件助手与 AI 配置

## 使用

1. 设置 → AI 设置：添加一个或多个 OpenAI 兼容供应商，填写 API 地址和 Key。
2. 选择一个支持文字和图片的多模态供应商及模型 ID。短信和图片共用此模型，配置后即可使用。
3. 取件助手点击“＋ → 扫描短信”，选择最近 1、2、3、7 天或自定义日期，点击“扫描并分析”并授予短信权限。所选范围尚未处理的短信经快速关键词过滤后发送给配置的 AI，提取后自动入库。
4. 模型返回固定字段后写入本机 SQLite：来源、取件码、运单、公司、地点、柜/站点、状态和截止提示。默认只看待取，可按地点、柜/站点、公司或时间分类排序。
5. 点击“已取件”归档，归档中可撤销。重复扫描跳过已处理来源；后续提醒不会自动恢复已取状态。同码复用等无法确定的情况保留待核对候选。

没有短信权限时可复制短信后，点击“＋ → 从剪贴板粘贴”导入。此操作立即读取剪贴板文字并分析入库，不再打开输入框或要求再次点击“分析并添加”；空白、非文字或超过 200000 字符的剪贴板会提示原因，不调用 AI。仅在您点击此入口时读取剪贴板，不在启动或后台自动读取。图片通过系统相册选择，使用同一多模态模型，结构与来源校验通过后直接入库。自动读取默认关闭，可在“取件助手 → 取件设置”启用并设置过去 1–93 天（含今天）。启用后打开应用时读取，60 秒内短时返回不会重复运行；此开关与天数仅保存在当前手机。关闭后不再发起新的自动读取，已经发送的请求仍可能完成。不会在应用关闭后定时轮询或监听新短信，不请求发送/删除短信权限。Android 将 READ_SMS 列为受限制权限，部分系统或安装器可能不允许授予；这种情况下使用粘贴/图片入口。

短信内容主要由模型提取。程序负责来源/格式/完整码校验、地点格式统一、幂等入库和取件状态，不执行短信中的网址或指令。一次请求最多20条/12000字符，超过时分批；返回不完整、截断或失败不将本批标为已处理，可重试。

0.6.11 优化分类提示：明确“取件码 + 指定地点/柜机 + 取件指令”为待取证据，无需出现“快递/包裹”字样，通知附带短链接不代表广告。丰巢为柜机品牌，承运商缺失时留空；通过完整 JSON 示例区分待取、已取、派送和普通验证码，并保留完整码、分段和原文截止提示。

当模型仅把某条短信判为非快递时，程序对严格匹配「【丰巢】凭取件码8位数字至…丰巢柜取件」的完整通知进行本机补救，直接使用原文码和地点，柜位按现有规则拆分。模板可附丰巢快递员短链接，但不会访问网址；缺码、分段码、其他签名、额外说明、营销或已取件内容及图片不适用此规则。模型已返回待取/派送/已取时保留其结果。原 AI 分类与“规则补救”数量分别记入日志；规则不能替代失败的 AI 请求或绕过来源校验。

从 0.6.8 起，识别说明明确覆盖「【驿小哥】…包裹已到…凭分段数字码来取」这类到站通知，不要求出现「取件码」三个字。保留完整分段码和原文截止提示，快递公司使用正文承运商，不能把短信签名服务商当成承运商。

如果短信以前被误判而没有生成快递记录，可在「＋ → 扫描短信」选择日期并勾选「重新识别未生成快递记录的短信」。这会把范围内以前未生成记录的已处理短信一并发给已配置的 AI；已有待取或归档记录的来源仍跳过。选项默认关闭，不改变打开应用时的自动读取行为；失败后仍可再次重扫。

## 读取诊断与运行日志

0.6.10 可在「设置 → 运行日志」查看、复制和清空日志；「＋ → 扫描短信 → 仅检查读取」也可直接打开日志。日志仅保存在应用私有目录，最多两份 128 KiB 文件，记录应用版本、系统和机型、扫描日期和时区、权限、读取/关键词匹配/过滤/重复/已处理跳过/待分析数量，以及 AI 分类、入库数量和安全错误类别。不保存短信正文、取件码、密钥、网址或模型原始响应，也不会自动上传日志。

「仅检查读取」无需配置 AI，不调用模型，不写入已处理标记。诊断显示系统短信收件箱总数、最新收件时间及所选范围的处理计数，可区分未读取到短信、关键词未匹配、已处理跳过和 AI 未生成记录。读取来源仍是 Android 系统短信收件箱；手机短信应用中的厂商专有消息是否开放给系统接口，需结合本机诊断判断。

「今天」及 2/3/7 天快捷范围会随当前日期更新，修复应用跨天保留旧日期的问题；手动选择的自定义日期继续保留。

0.6.11 将已处理来源分为已有待取记录、已有归档记录、已分析无关联记录。手动扫描没有待分析来源，但有以前分析过且未生成记录的短信时，可在结果弹窗点击「重新识别」直接重试，取消不调用 AI、不改标记；自动读取继续跳过已处理来源。已有待取及归档记录不会因重扫重复导入。历史标记未保存具体分析时间或原始分类，不能据此猜测何时或为何处理过。

0.6.12 可在「扫描短信 → 仅检查读取 → 查看原文」，或未生成记录的重试弹窗中查看系统接口实际返回的短信。列表显示范围内最近100条，可点开查看完整正文并复制；查看不调用 AI、不改处理标记。复制保留接口原始文字，空正文不能复制。手机短信应用中的可见内容是否与接口返回一致，应以此对照确认，不能仅凭接收时间相同断定正文相同。

日志新增读取和 AI 输入概要：正文字符数、空正文、丰巢标记、取件码标签、取件指令、格式字符和完整模板数量，以及经过限制的常见模型名、协议类型及补救规则未命中提示。仍不写入短信正文、发件人、取件码或密钥。读取按列名定位字段，兼容返回列顺序有差异的接口。

## 短信快速过滤与思考强度

0.6.9 默认开启快递短信快速过滤，在「取件助手 → 取件设置 → 短信快速过滤」可查看、编辑、关闭和恢复默认词库。默认 114 个关键词覆盖取件、派送、投递、签收、承运商、驿站、柜机，以及英文通知；包括驿小哥、菜鸟速递、菜根谭。正文或发送方包含任一关键词即可进入 AI 分析，大小写不敏感、兼容全角文字，不使用关键词判定最终快递状态。

关键词每行一个，也可用中英文逗号、分号分隔；自动去重，最多 256 个、每个最多 80 字符。开启时不可保存空词库。恢复默认只填入编辑界面，点击保存才生效；取消保留原设置。

自动读取、手动扫描和漏识别重扫共用过滤规则；剪贴板与图片导入直接分析，不受关键词限制。被过滤的短信不会被标为已处理，增加关键词或关闭过滤后可重新扫描。关键词与过滤开关仅保存在本机，不随 AI 配置同步。

「AI 设置 → 多模态模型 → 思考强度」可选模型默认、关闭思考、低、中、高，随「保存功能模型」保存。旧版未发送思考控制参数，是沿用模型默认，不能推断为关闭。默认档保持此行为；其他档位明确发送思考控制。此设置也仅保存在本机，不扩展 PC 共享配置格式。

Qwen 使用 enable_thinking；普通 Qwen 的低/中/高预算为 4096/16384/32768 tokens，Qwen3.8-Omni 使用 low/medium/xhigh 档。DeepSeek 直连使用 thinking.type，强度映射 low/high/max；百炼 DeepSeek 使用 enable_thinking。其他 OpenAI 兼容服务使用 reasoning_effort=none/low/medium/high，使用 max_completion_tokens 并省略温度参数。模型支持范围不同；服务返回 HTTP 400 时会提示改为模型默认或选择支持思考的模型，不静默关闭思考重试。仅最终 content 用于入库，reasoning_content 不作为取件结果。参数依据 [百炼 Chat API](https://www.alibabacloud.com/help/zh/model-studio/qwen-api-via-openai-chat-completions)、[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[OpenAI Chat API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

## 手动编辑快递信息

在快递卡片右侧点击「⋮ → 编辑信息」，可修改取件码、运单号、快递公司、地点、柜位和截止提示。点击保存后立即更新列表及分类，取消不会修改记录；已归档的快递同样可编辑，取件状态、原始短信/图片来源和接收时间保留。编辑仅在本机完成，不调用 AI。

只保护实际改动过的字段，后续 AI 提醒不会覆盖这些手动修改；未改过的字段仍能从新短信中补充。修改前的包裹标识用于后续提醒去重，原有同码不同柜、72 小时匹配范围及歧义核对规则继续生效。若编辑期间记录被后台更新，保存会提示重新打开，避免覆盖新变化。地点中的明确室内、室外和柜号仍按统一规则移到柜位。

## 地点一致性

从 0.6.5 起，每批入库都使用相同的本机整理规则：地点只保留站点主体，尾部明确的室内、室外、柜号和快递柜信息移到柜位。例如「南大仙林菜根谭室内 + 9号丰巢柜」与「南大仙林菜根谭室外39号 + 丰巢柜」均归入「南大仙林菜根谭」，分别保留「室内9号丰巢柜」和「室外39号丰巢柜」。升级时也整理已保存的待取与归档记录，保留取件码、来源和取件状态。普通门牌（如仙林路39号）不拆分，室内/室外信息冲突时保留原信息供核对，不按文字相似度自动合并不同站点。

若 AI 使用简称或别名，打开「取件助手 → 取件设置 → 整理地点」，勾选同一站点的名称，输入统一名称，预览影响的记录和目标名称后确认。整理覆盖已归档记录，只改地点分类，不合并包裹或柜位；规则保存在本机，以后分批导入同样的别名会沿用统一名称。按柜查看时同时显示站点，避免不同站点的同号柜被分到一起。整理不再调用 AI，也不重新上传短信。

## 与 PC 同步配置

AI 设置集中在「WebDAV 与备份 → 配置备份」中随配置一起上传、预览和恢复。两端使用同一 WebDAV 地址、账号、密码和根目录，新备份保存在 `<根目录>/config-backups/shared`。恢复电脑备份时只导入共享 AI 设置；手机首页和 NAS 偏好保留。旧版 AI 备份仍显示在此列表。

备份未包含的本机取件模型继续保留。供应商同名 ID 但地址或密钥不同时，会保留独立的本机供应商，避免取件角色引用错误密钥。

配置和 API Key 采用 PBKDF2-HMAC-SHA256（200000 次）派生 AES-256-GCM 密钥，复用 WebDAV 连接密码；API Key 在各端重新用本机安全存储加密。修改 WebDAV 密码后，需从保留配置的设备重新上传。

AI 配置同步不包含短信、图片或取件数据库。模型判断可能出错，可以查看原始来源核对。0.6.8 已用电脑现有配置的 qwen3.8-flash 实测一条驿小哥到站通知，完整分段码、承运商、站点和时刻均正确；这不代表其他模型或全部短信准确率。自动化回归使用合成短信与模拟接口。
